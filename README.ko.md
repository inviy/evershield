# evershield

**당신의 유료 기능, 사실은 CSS로만 가려져 있을지 모릅니다.** evershield는
요금제별 사용자가 API 응답과 페이지에서 실제로 무엇을 받는지 확인하고,
무료 사용자가 Pro 데이터를 들고 있으면 빌드를 실패시킵니다.

[English](README.md)

## 왜 만들었나

제 사이드 프로젝트에 "Pro 전용" 지표가 있었습니다. 무료 사용자에게는
흐리게(blur) 처리하고 자물쇠 아이콘을 얹었습니다. 잠긴 것처럼 보였습니다.
그런데 개발자 도구를 열어 보니, 진짜 숫자가 모든 무료 사용자의 JSON
응답에도, 블러 아래 DOM에도 그대로 있었습니다.

가지고 있던 도구 어느 것도 이걸 유출로 보지 않았습니다. 비밀값 스캐너는
숫자를 잡지 않고, 린트도 테스트도 통과했고, 화면은 시킨 대로 동작했습니다.
버그는 "서버가 데이터를 보내고, 화면이 안 보여주기로 한 것" 자체였습니다.

## 어떤 문제인가

직접 만들든 AI 코딩 에이전트가 만들든, 유료 플랜은 이렇게 만들어지기
쉽습니다. API는 전체 객체를 내려주고, 화면이 플랜에 없는 부분을 흐리게,
숨기게, 잠기게 처리합니다. 개발자 도구 탭 하나면 보이고, 웹앱을 역공학하는
에이전트 도구는 이제 이걸 자동으로 읽어 갑니다.

| 겉보기 | 무료 사용자가 실제로 가진 것 |
|---|---|
| Pro 숫자는 블러, 카드엔 자물쇠 | DOM 안의 그 숫자 |
| 차트 자리에 "업그레이드하면 보여요" | API 응답 안의 차트 데이터 |
| 깔끔한 프로덕션 빌드 | 번들 안의 결제 키, `.map` 안의 원본 소스 |

## evershield가 하는 일

설정한 신원(비로그인, free, pro …)마다 앱을 호출해서 각자 받은 것을
비교하고, 낮은 플랜이 높은 플랜의 데이터를 받으면 CI를 실패시킵니다.
사용자가 보는 화면부터 번들까지 세 곳을 봅니다.

| 계층 | 명령 | 잡는 것 | 예 |
|---|---|---|---|
| **3 · Surface** | `surface` | 서버가 빼지 않고 CSS로만 가린 데이터 | 무료 페이지 DOM에 있는 블러 처리된 Pro 숫자 |
| **2 · Response** | `audit` | 낮은 플랜 API 응답에 들어간 높은 플랜 필드 | 모든 무료 사용자 JSON에 있는 "Pro 전용" 지표 |
| **1 · Artifact** | `scan` | 빌드나 npm 패키지에 든 키, 내부 주소, 소스맵 | 번들 안의 결제 키, 배포된 `.map` |

모든 결과에는 파일·응답 경로·DOM 선택자, 확신도, 고치는 방법이 붙습니다.
찾은 비밀값은 절대 전부 출력하지 않습니다(앞뒤 4글자만).

## 30초 체험

```bash
npx evershield demo                                # 1·2계층, 설정 없음
npx playwright install chromium                    # 3계층용 브라우저, 한 번만
npx -p evershield -p playwright evershield demo    # 세 계층 모두
```

`npx evershield demo --fixed`는 고친 뒤의 같은 앱을 돌려서 아무것도
보고하지 않는 것을 보여줍니다.

## 누구에게 쓸모 있나

- **쓸모 있는 경우:** 무료·유료 플랜이 있는 웹앱을 운영하고, 특히 빠르게
  또는 AI 코딩 에이전트로 만들었고, 플랜 경계가 새기 전에 CI에서 막고 싶을
  때. 1계층만으로도 npm 패키지 배포 전 게이트로 쓸 수 있습니다
  (`npm pack` 후 `npx evershield scan <패키지>.tgz`).
- **맞지 않는 경우:** 남의 서비스 취약점 찾기, 모의해킹 대체, 저장소
  히스토리용 비밀값 스캐너 대체.

## 솔직한 한계

- 2·3계층은 설정이 필요합니다. 플랜별 테스트 계정(토큰이나 저장된 브라우저
  세션을 환경변수로), 검사할 엔드포인트와 페이지, 플랜별로 받으면 안 되는
  것을 적어야 합니다. 10~30분 정도 걸립니다.
- 적어 준 것만 검사합니다. 빠뜨린 엔드포인트나 페이지는 검사되지 않습니다.
- 1계층은 빌드 디렉터리도 검사할 수 있는 gitleaks, trufflehog와 겹칩니다.
  둘 다 돌리세요. evershield가 더하는 건 빌드 구조를 아는 필터링, 앱 패키지와
  npm tarball 지원, 세 계층 공통의 게이트와 SARIF 출력입니다.
- 사전 공개 단계이고 관리자는 한 명, 실제 서비스 검증은 아직 한 곳(위 사이드
  프로젝트)뿐입니다. 지금 가장 도움이 되는 건 이슈와 오탐 제보입니다.

## 실제 코드로 잰 오탐

규칙이 바뀔 때마다 [오탐 코퍼스](docs/corpus.md)로 검사합니다. 브라우저로
배포되는 npm 패키지 42개(React, Vue, Firebase, Supabase, Auth0, Sentry,
Stripe.js 등)와 Next.js·Vite·SvelteKit·Astro·Expo 기본 앱 10개를 실제
배포 형태로 빌드해서 돌립니다. **기본 게이트 기준 오탐 0건**(파일 8,886개,
175MiB). 막히는 1건은 실제 유출(인라인 소스맵이 든 개발 빌드)입니다.

## 시작하기

```bash
npx evershield init              # evershield.config.json과 GitHub 워크플로 생성
npm run build
npx evershield scan ./dist       # Next.js는 ./.next, 종료 코드 0이면 막을 것 없음
```

## 원칙

- **방어 전용.** 설정에 적은, 내가 소유한 대상만 검사합니다.
- **로컬 전용.** 어떤 데이터도 밖으로 나가지 않습니다. 원격 수집 없음.
- **증거 우선.** 모든 결과에 위치와 확신도가 있습니다. 소음은 버그입니다.
- **CI 우선.** 안정된 종료 코드, JSON·SARIF 출력.
